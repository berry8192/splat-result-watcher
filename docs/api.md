# WebSocket API

splat-result-watcher は、認識した試合の情報を WebSocket で JSON として配信します。
このページは受信側のアプリケーションを作る方向けの説明です。約束事の正本は [protocol.md](protocol.md) で、
食い違いがあればそちらが優先されます。

## 接続

| 項目 | 内容 |
|---|---|
| URL | `ws://127.0.0.1:3140/events`（ポートは設定「接続」で変更できます。待ち受けは 127.0.0.1 のみ） |
| クエリ | `?after=<最後に受け取った seq>`。省略すると 0 として扱われ、保存されているイベントをすべて受け取ります |
| 形式 | UTF-8 の JSON。1 フレームに 1 イベント |
| 役割 | splat-result-watcher がサーバー、受信側がクライアントです |

接続直後、サーバーは次の順で送ります。

1. `hello`
2. `seq` が `after` より大きいイベントを、古い順にすべて
3. 現在の `status`
4. 以降、発生した順にイベントを送ります

サーバーは少なくとも 5 秒ごとに `status` を送ります。15 秒間なにも届かなければ切断とみなし、
3 秒後に再接続することを推奨します。再接続時は最後に受け取った `seq` を `after` に付けてください。

## 共通のフィールド

| フィールド | 内容 |
|---|---|
| `type` | イベントの種類（下の一覧） |
| `seq` | イベントごとの通し番号。アプリを再起動しても戻りません（ファイルに保存）。`hello` と `status` には付きません |
| `match_id` | 試合の識別子（例 `20260928-2104-01`）。同じ試合のイベントは同じ値を持ちます |
| `at` など時刻 | すべて RFC 3339（UTC） |

分からない項目は省略されるか `null` になります。受信側は未知のフィールドと未知の値を無視し、
エラーにしないでください。

### 値の一覧

| フィールド | 値 |
|---|---|
| `mode` | `x`（X マッチ）/ `bankara_challenge` / `bankara_open` / `other`（ナワバリ・イベント・プラベ・フェスなど） |
| `rule` | `area` / `yagura` / `hoko` / `asari` / `turf_war`（ナワバリバトル。`mode` は `other`） |
| `outcome` | `win` / `lose` / `no_contest` / `lose_uncounted` |
| `kind` | `x`（X パワー）/ `udemae`（ウデマエポイント） |
| `state` | `no_signal` / `idle` / `in_battle` / `reading` / `post_match` |

## イベント一覧

| `type` | `seq` | 意味 |
|---|---|---|
| `hello` | なし | 接続直後の挨拶。アプリ名・バージョン・最新の `seq` |
| `status` | なし | 現在の状態。5 秒ごとにも送られます |
| `battle_started` | あり | 試合の開始（ルール紹介の画面） |
| `result` | あり | 試合の勝敗 |
| `power` | あり | X パワー・ウデマエポイントの変動（セットの終わり） |
| `set_progress` | あり | 現在のセットの勝敗数 |
| `observed` | あり | 試合と結び付かない、メニューなどで見えた現在の値 |
| `lobby` | あり | ロビーのメニューで選んでいるモードとルール |
| `manual` | あり | 放送者が手で直した値（直した後の値） |

### `hello`

```json
{"type":"hello","app":"splat-result-watcher","version":"0.1.0","last_seq":42}
```

`last_seq` が受信側の保存している `seq` より小さいときは、サーバー側で記録が作り直されています。
`after=0` で接続し直してください。

### `status`

```json
{"type":"status","state":"in_battle"}
```

| `state` | 意味 |
|---|---|
| `no_signal` | 映像をキャプチャできていない |
| `idle` | 待機（ロビーなど） |
| `in_battle` | 試合中 |
| `reading` | 結果の画面を認識中 |
| `post_match` | 試合後の画面（パワーの変動・セット進行など） |

### `battle_started`

```json
{"seq":43,"type":"battle_started","match_id":"20260928-2104-01","at":"2026-09-28T12:04:10Z","mode":"x","rule":"hoko"}
```

| フィールド | 内容 |
|---|---|
| `rule` | 試合を始めたときのルール。ローテーションをまたいだ試合も、このルールで数えます |
| `mode` | 分かるときだけ付きます（マッチング画面やナワバリの紹介から判定できたとき） |

### `result`

```json
{"seq":44,"type":"result","match_id":"20260928-2104-01","outcome":"win",
 "mode":"x","rule":"hoko","started_at":"2026-09-28T12:04:10Z","ended_at":"2026-09-28T12:09:02Z"}
```

| `outcome` | 意味 | 数えるか |
|---|---|---|
| `win` | 勝ち | 数える |
| `lose` | 負け | 数える |
| `no_contest` | 無効試合（開始直後の切断など） | 数えない |
| `lose_uncounted` | 切断により「負けとしてカウントされませんでした」が付いた負け | 数えない |

`mode` が `other` の試合も区切りとして送られますが、セットやポイントには数えないでください。
`started_at` は必ず付きます。

### `power`

```json
{"seq":45,"type":"power","match_id":"20260928-2104-01","kind":"x","rule":"hoko",
 "before":1938.5,"after":1983.5,"calibrating":false,"at":"2026-09-28T12:09:30Z"}
```

| フィールド | 内容 |
|---|---|
| `kind` | `x`: X パワー（0.1 刻み）。`udemae`: ウデマエポイント（整数。負の値もあります） |
| `rule` | `kind` が `x` のとき。X パワーはルールごとです |
| `before` / `after` | 変動の前後の値。`before` が読めなかったときは `null` |
| `calibrating` | `true` のとき計測中（ルールごと・シーズンごとの最初の 5 戦）。`after` は付きません |

X パワーはセット（3 勝または 3 敗）の終わりに、ウデマエポイントはチャレンジの精算時にまとめて、
オープンでは 1 試合ごとに送られます。昇格でポイントがリセットされたときは `before: null`・`after: 300` です。
精算画面のポイントの数字が読めないときは、画面の増減（「= -13p」など）を直前に分かっていた値に足して送ります
（直前の値が分からなければ送りません）。

`power` は、同じ試合の `result` より必ず後に送られます。受信側は `power` を受け取った時点で
そのセットを締め、次のセットを 0 勝 0 敗から数え直すことを想定しています。

### `set_progress`

```json
{"seq":46,"type":"set_progress","match_id":"20260928-2104-01","wins":2,"losses":1}
```

試合後のセット進行の画面から読んだ、現在のセットの勝敗数です。3 勝目・3 敗目の後はこの画面が出ないため、
セットの終わりは `power` で判断してください。

### `observed`

```json
{"seq":47,"type":"observed","kind":"x","rule":"hoko","value":1983.5,"wins":1,"losses":0,"at":"2026-09-28T12:10:00Z"}
```

ロビーのメニューやマッチング中の画面で見えた、現在の値です。試合と結び付かないため `match_id` はありません。
バンカラマッチ（チャレンジ）の参加費を支払ったときは、支払った後のウデマエポイントを、チャレンジのマッチングか
試合が始まったときに送ります。

| フィールド | 内容 |
|---|---|
| `value` | X パワーまたはウデマエポイント。文字が読めずランプだけ見えたときは省略されます |
| `wins` / `losses` | セットの進行が見えたときだけ |
| `rank` | `kind` が `udemae` のとき、メニューで読めたウデマエのランク（`"C-"` 〜 `"S"`、`"S+0"` 〜 `"S+50"`）。読めなければ省略されます |

同じ値は続けて送られません。受信側は値が食い違っていれば補正に使い、セットは締めないでください。

### `lobby`

```json
{"seq":48,"type":"lobby","mode":"bankara_open","rule":"asari","at":"2026-09-28T12:11:00Z"}
```

ロビーのメニューで選んでいるモードとルールです。選択が変わって落ち着いたときに送られます（試合中は送られません）。
`rule` は読めなかったときは省略されます。表示ウィンドウはこれを見て、試合が始まる前からモードとルールを切り替えます。

### `manual`

```json
{"seq":49,"type":"manual","kind":"x","rule":"hoko","value":2250.0,"wins":2,"losses":1,"at":"2026-09-28T12:12:00Z"}
```

認識アプリの設定ウィンドウの「手動操作」で、放送者が手で直した値です。**差分ではなく直した後の値**なので、
同じイベントが何度届いても結果は変わりません。

| フィールド | 内容 |
|---|---|
| `kind` | `x` / `udemae` |
| `value` | 直した後のパワーまたはウデマエポイント。付いているときだけ上書きしてください |
| `wins` / `losses` | 直した後のセットの勝敗数。付いているときだけ上書きしてください |
| `rule` | `kind` が `x` のとき |

`match_id` は付きません。セットは締めないでください。放送者自身の操作なので、試合中にも送られることがあります。
無視しても構いません。

## 守られる順序

- 試合中（`state` が `in_battle` の間）に送られるのは `status` と `battle_started`、それに放送者の操作による `manual` だけです。
  勝敗やパワーは試合が終わってからしか送られません（対戦相手に有利・不利となる情報を出さないため）。
- 同じ試合の `result` は、その試合の `power` より先に送られます。
- バンカラの `result` は、チャレンジかオープンかが判定できるまで少し遅れることがあります（勝敗の画面の直後ではなく、
  精算やセット進行の画面を見た後）。

## 受信側で考慮すること

- **重複**: 同じ試合のイベントは、再接続時の再送などで複数回届くことがあります。`match_id` で 1 回だけ数えてください。
- **取りこぼし**: 認識できなかった試合はイベントが欠けます。`power` が届いたらセットを締めることで、ゲーム側の状態と揃います。
- **古い再送**: 30 分より前に終わった試合の再送は、現在のセットに数えないことを推奨します。
- **未知の値**: 新しい `type`・`rule`・`outcome` が増えることがあります。無視して動作を続けてください。

## 1 試合の流れの例

```
{"type":"hello","app":"splat-result-watcher","version":"0.1.0","last_seq":100}
{"type":"status","state":"idle"}
{"seq":101,"type":"observed","kind":"x","rule":"area","value":2219.4,"at":"..."}
{"seq":102,"type":"battle_started","match_id":"20261006-0215-61","at":"...","mode":"x","rule":"area"}
{"type":"status","state":"in_battle"}
{"type":"status","state":"reading"}
{"seq":103,"type":"result","match_id":"20261006-0215-61","mode":"x","outcome":"win","rule":"area","started_at":"...","ended_at":"..."}
{"type":"status","state":"post_match"}
{"seq":104,"type":"set_progress","match_id":"20261006-0215-61","wins":1,"losses":0}
{"type":"status","state":"idle"}
```

セットの 3 勝目では `set_progress` の代わりに `power` が届きます。

```
{"seq":111,"type":"result","match_id":"20261006-0207-60","mode":"x","outcome":"win","rule":"area","started_at":"...","ended_at":"..."}
{"seq":112,"type":"power","match_id":"20261006-0207-60","kind":"x","rule":"area","before":2169.4,"after":2219.4,"calibrating":false,"at":"..."}
```
